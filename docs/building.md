# Building, installing, tuning

## Requirements

- CUDA 12.0 or newer and GNU make.
- A host compiler your CUDA accepts. The Makefile uses `g++-12` when it is installed (CUDA 12.0–12.3
  reject GCC 13); otherwise nvcc's default. Override with `CCBIN=...`.
- Python 3 only for one of the tests; PyTorch only for the bindings ([binds/python](../binds/python/README.md)).

## Make targets

```sh
make lib                    # out/libe5m2effma.a for sm_50 52 53 60 61 62 70 72 75 80 86 87
make lib ARCHS=native       # only the architecture of GPU $(GPU), detected with nvidia-smi
make lib ARCHS="61 75 86"   # any subset
make test                   # bit-exact and exhaustive tests on GPU $(GPU) (default 0)
make bench                  # GEMM / GEMV / Adam vs cuBLAS and memory bandwidth
bench/run_bench.sh          # controlled run (board settings, cool-downs) -> benches/<gpu>.md
make tune                   # tune the kernels for GPU $(GPU) -> src/e5m2effma_tuned.h
make install PREFIX=...     # header, static library, pkg-config file
```

Variables: `ARCHS`, `GPU`, `CUDA_HOME` (default `/usr/local/cuda`), `CCBIN`, `JOBS`, `JOB_MB`,
`OBJDIR` (where the multi-architecture objects go), `PREFIX`, `DESTDIR`.

The library ships SASS only (no PTX), so it is never JIT-compiled onto GPUs it was not built for — in
particular not onto sm_89+, which has native FP8; building for those targets stops with `#error`. A
GPU missing from `ARCHS` gets a clear error at run time (`e5ma_last_error`).

## Parallel build

The build runs in parallel by default with `JOBS = min(cores, ½ · MemAvailable / JOB_MB)`
(`JOB_MB = 512`; one nvcc process peaks at about 110 MB). `make JOBS=n` overrides it; a plain `-j` on
the command line is overridden. When there are more job slots than objects, the objects also compile
their architectures in parallel (`nvcc --threads`).

Kernel instances are split into small objects of similar cost (GEMM: configuration × A dtype × B dtype;
GEMV: configuration × A dtype × x dtype), and each architecture's SASS contains kernel bodies only for the
configurations its table selects (trapping stubs elsewhere). On a 20-thread CPU the library for all 12
architectures builds in about 130 s, one architecture in about 10 s.

## Installing for C / C++

```sh
make install PREFIX=$HOME/.local ARCHS="61 75 86"
cc app.c $(pkg-config --cflags --libs e5m2effma)     # PKG_CONFIG_PATH=$HOME/.local/lib/pkgconfig
```

The pkg-config file adds the CUDA include directory and `-lcudart -lstdc++`. Without installing,
include `include/e5m2effma.h` and link `out/libe5m2effma.a` plus the CUDA runtime. The library is
compiled with `-fPIC`, so it can be linked into shared objects (the Python extension does that).

## Tuning

`make tune` benchmarks every GEMM / GEMV candidate ([design.md](design.md#kernel-configurations)) on
GPU `$(GPU)` and writes the winners for its compute capability to `src/e5m2effma_tuned.h`; entries
for other compute capabilities in that file are kept, so one table can be built on several machines.
A candidate replaces the default only if it is at least 2 % faster, so noise does not add kernels to
the library. Rebuild the library afterwards.

At run time the library uses the entry for the device's compute capability, or the defaults for GPUs
without one. A GPU that runs binary-compatible SASS of another minor version (say, a library built for
sm_60 on an sm_61 card) falls back to the defaults automatically, since that SASS only carries the
defaults' kernel bodies. Tuned entries for GPUs other than the GTX 1080 are very welcome as pull
requests.

## Project layout

```
include/e5m2effma.h          public C API
src/e5m2effma.cuh            core: exact E5M2 / E4M3 decode and encoding, BF16 rounding, typed loads /
                             stores, GEMM / GEMV epilogue, per-architecture kernel tables
src/e5m2effma.cu             e5ma_cast, errors (e5ma_last_error), kernel table for the current device
src/e5m2effma_tuned.h        tuning results (generated by `make tune`)
src/gemm_e5m2effma.cuh       GEMM kernel template and its configuration candidates
src/gemm_e5m2effma.cu        e5ma_gemm: validation, routing to GEMV, configuration choice
src/gemm_e5m2effma_inst.cu   GEMM instances (one small object per config × A × B dtype)
src/gemv_e5m2effma.cuh       GEMV kernel template and its configuration candidates
src/gemv_e5m2effma.cu        GEMV configuration choice
src/gemv_e5m2effma_inst.cu   GEMV instances (one small object per config × x dtype)
src/adamw_e5m2effma.cu       e5ma_adam (Adam / AdamW)
binds/python/                PyTorch bindings: pip package `e5m2effma`
tune/tune.cu                 tuner
tests/                       C tests (see testing.md) and the exact reference model
bench/                       bench_gemm, bench_gemv, bench_adamw; run_bench.sh + report.py (benches/)
benches/                     benchmark results: table.md (one row per GPU), <gpu>.md (full runs)
docs/                        this documentation
```
