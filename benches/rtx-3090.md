# NVIDIA GeForce RTX 3090

Community result (thanks to [@datspike](https://github.com/datspike)), measured with the sibling
library **E4M3EffMA 0.1.0** (`bench/run_bench.sh` with its CUDA 13.3 build fix), not with E5M2EffMA:
the two libraries share their kernels — E5M2 decoding differs from E4M3 only in shift and scale
constants, the instruction sequence is the same — so these are the expected numbers for E5M2 operands
until someone runs this repository on an RTX 3090. Transcribed from the contributor's report; rows the
report did not list are left out. Methodology and how to read them: [docs/performance.md](../docs/performance.md).

reference corpus).

## GEMM, M = N = K = 4096

| Operation | Time | GMAC/s | % of FP32 peak | vs cuBLAS SGEMM TN |
|---|---:|---:|---:|---:|
| effma_gemm TN E4M3 -> BF16 | 6.674 ms | 10296 | 48.7 % | 1.10× |
| effma_gemm NN E4M3 -> BF16 | 6.448 ms | 10658 | 50.5 % | 1.14× |
| effma_gemm NT E4M3 -> BF16 | 6.144 ms | 11185 | 59.5 % | 1.20× |
| effma_gemm TT E4M3 -> BF16 | 6.358 ms | 10808 | 52.2 % | 1.16× |
| effma_gemm TN E4M3 x BF16 -> BF16 | 6.623 ms | 10376 | 49.2 % | 1.11× |
| effma_gemm TN E4M3 x FP32 -> BF16 | 6.661 ms | 10316 | 56.5 % | 1.11× |
| cuBLAS SGEMM NN FP32 -> FP32 | 5.963 ms | 11525 | 54.6 % | — |
| cuBLAS SGEMM TN FP32 -> FP32 | 7.363 ms | 9334 | 44.2 % | — |

On this GPU cuBLAS is much faster in the NN layout than in TN: against SGEMM NN the FP8 GEMM is
0.89–0.97×. These kernels are the FP32-FFMA ones tuned on Pascal (no tuned entry for sm_86 yet, no
Tensor Cores, no `cp.async`).
